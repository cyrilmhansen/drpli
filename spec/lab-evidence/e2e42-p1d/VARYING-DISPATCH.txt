SECTION 3 -- the two numbers that show the defect was storage, not syntax
-------------------------------------------------------------------------
Same declaration, two spellings:

  dcl (line char(14), buff char(254)) varying;      <- COPYLPT's spelling
  dcl line char(14) varying, buff char(254) varying; <- the scalar spelling

DR's $L$D$S dump for BOTH is:
  c 0000 LINE CHAR(14) VARYING AUTOMATIC
  c 000F BUFF CHAR(254) VARYING AUTOMATIC
(the scalar spelling is E46J1-class evidence in golden/e42p1d; the group spelling is E46J2/E46J17).
000F = 15 = 14 + the length byte.  Before P1d this compiler printed 000E for the group spelling --
CHARACTER(14) with NO length byte -- so BUFF, and everything after it, sat one byte low, and the
frame was 270 where DR's is 272.  COPYLPT itself measured 276 against DR's 278 (E46J13).

That is why the symptom was a wrong helper rather than a wrong name: ?SLVTS reads the length OUT
OF the descriptor cell, ?SLCTS takes it as a `MVI A' immediate, and choosing between them is a
read of the storage class the binder produced.  Fixing the binder moves the classification, the
layout, the dump and both operations' dispatch at once; no TITLE-specific or PUT-specific branch
was added, and [C174]'s dispatch table is untouched.

SECTION 4 -- what still refuses, and why that is the honest state
-----------------------------------------------------------------
Five probes are DR's own rejections and are registered on the negative panel as `dr-refuses':
E46J8, E46J9, E46J10, E46J15, E46J19 (CONFLICT, no .REL).  VARYING attaches to CHARACTER and to
nothing else; DR applies it per ITEM, so E46J19's listing shows A and C becoming VARYING while
B (FIXED) is the CONFLICT.  This compiler cannot emit a partially-diagnosed object, so the
declaration refuses as a whole -- same OUTCOME (no object), and the message names DR's word.

Six are MY gaps (`my-gap' on the panel), because DR emits a real object for each:
  E46J6, E46J11, E46J12, E46J18, E46J21  -- a level-numbered structure's CHARACTER member, in
      both the bare and the qualified spelling.  Bind now lays these out exactly as DR does (see
      E46J21 below, where our own dump equals DR's line for line); what is missing is the ALIAS,
      because bind's member registry covers FIXED BINARY(15) and POINTER only [E2E-39/P2].
      Widening it would resolve assignment, comparison, EDIT and PUT EDIT for members through
      routes that have no member sample, so the refusal is kept and, since P1d, says which
      member and which type it is refusing.
  E46J14 -- `dcl x varying;' with no type at all: DR dumps `X(0) VARYING AUTOMATIC' in a block of
      AUTO STORAGE 0 (no cell), assigns through ?DLDOP and prints through ?PNVOP, i.e. the dump
      says VARYING and the code treats it as a number.  Nothing pins a READ of that name.
