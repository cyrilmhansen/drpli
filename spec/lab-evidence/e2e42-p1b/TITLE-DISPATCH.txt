# [E2E-42/P1b] THE TITLE ROUTE IS A DISPATCH ON THE OPERAND, PROVEN BY LINK RECORDS

Reproduce from the repository root:

    for f in golden/e42p1c/E46F1/E46F1.REL golden/e42p1c/E46F2/E46F2.REL \\
             golden/e42p1c/E46F3/E46F3.REL golden/e42p1c/E46F4/E46F4.REL \\
             golden/e42p1b/E46D6/E46D6.REL golden/first/LOAN2/LOAN2.REL \\

      echo "== $f"; python3 tools/reldump.py "$f" | grep CHAIN-EXT

WHY RECORDS AND NOT MNEMONICS.  A `CALL ?SLCTS' and a `CALL ?SLVTS' are the same three bytes
(CD 00 00) in an unlinked .REL: the target is a LINK-CHAIN-EXT record, not an operand.  So the
only thing inside a DR object that distinguishes the two routines is the NAME field of the chain
record whose code address is the CALL's.  Reading that name is what makes this a measurement
rather than a guess, and it is why [C288] cites this file and not only the disassembly.

The OPEN block's own extent for every historical site below comes from
spec/lab-evidence/e2e41-p0/OPEN-BLOCKS.txt, which locates blocks by chain anchor plus backward
walk over instruction starts (the same [C125]/[C137] discipline), and DR's code addresses in
this file are inside those ranges.

WHAT THE DUMPS ESTABLISH

1. E46F1 -- `dcl nm char(14) varying', `open file(outf) stream output title(nm);
   put file(outf) list("X");' -- carries BOTH helpers in one module: ?SLVTS at code 000A,
   inside the OPEN block (DR-VERDICTS section 5 prints it as 0006..001F), and ?SLCTS at
   code 0033, which is the program's own PUT LIST literal.  Same statement, two routines,
   chosen by the operand.  Nothing about the option word distinguishes the two sites.

2. E46F2 -- `dcl nm char(8)' and otherwise an IDENTICAL program -- emits ?SLCTS at code
   000C and NO ?SLVTS ANYWHERE IN THE OBJECT.  Changing only the variable's storage class
   changed the routine, and the call at 000C is nine bytes into the block, i.e. at the
   title site and nowhere else.  That isolates the dispatch: the route is a property of the
   OPERAND, not of `title' and not of `stream output'.

3. E46F3 (varying, `stream input', ?SLVTS at 000A) and E46F4 (varying on a TEN-character
   FILE name, ?SLVTS at 000A) show the route is the same on the input side and that it
   COMPOSES with the long-name rule [C283] instead of competing with it: E46F4's object has
   both /ABCDEFGH/'s clipped LINK symbol and the ?SLVTS title chain.

4. E46D6 (literal title on a long name) emits ?SLCTS at 000C alone -- the [C278] route, byte
   exact since E2E-41/P2b.  Literal, VARYING and FIXED are therefore the whole measured
   vocabulary of a TITLE operand and there is no fourth form.

5. DR's OWN five variable-title sites, and this is the half of the table that is historical
   rather than mine:

     LOAN2     00CD..00E8 title(name)         -> ?SLVTS at 00D1   (the 00AD..00CA block is
                                                    title('$con'), ?SLCTS at 00B3)
     COPYLPT   014C..016D title(line)         -> ?SLVTS at 0150
     COPYLPT   01E8..020A title(line)         -> ?SLVTS at 01EC
     RETRIEVE  00C1..00E3 title(filename)     -> ?SLVTS at 00C5   (its 0006..0023 block is
                                                    title('$con'), ?SLCTS at 000C)
     CREATE    0037..0052 title(filename)     -> ?SLVTS at 003B

   All five take ?SLVTS, and in the three programs that also have a literal title the LITERAL
   takes ?SLCTS in the same object.  So [C288]'s dispatch is DR's behaviour on five historical
   sites plus four of mine, and E46F2's fixed operand is the ONLY case where a variable name
   reaches ?SLCTS -- which is what makes the rule "route by storage class" rather than "any
   non-literal goes to ?SLVTS", the reading this compiler had before and which [C288] corrects.

6. What the dumps do NOT say.  No object here puts a title through ?SLVTS from an
   EXPRESSION, a qualified reference (`x.y'), an ARRAY element, or a STATIC variable:
   LOAN2's `name' is `char(14) varying STATIC initial(...)' and that program is refused here
   for [C114]'s reason BEFORE any title code is emitted, so static title operands remain
   unmeasured and `open_title' refuses them by name rather than assuming they are ?SLVTS.
