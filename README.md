# PL/I-80 — historical reimplementation project

Reverse-engineering of the Digital Research **PL/I-80 Compiler v1.4**
(CP/M-80, 1983) with the long-term goal of an OCaml reimplementation.

Method: scientific — no claim about compiler behavior is accepted without
an experiment against the original binaries. Live truth source:
[`spec/CLAIMS.md`](spec/CLAIMS.md). Grammar work:
[`grammar/pli80.ebnf`](grammar/pli80.ebnf).

## Layout

- `artefacts/` — original distribution (treat as READ-ONLY ground truth)
- `manuals/`   — DR manuals (scans + SHA256), `extracted/` = OCR text
- `oracle/`    — neutral oracle: z80pack `cpmsim -8` (pure Intel 8080)
  - `run.py`     tiny pty console driver (no external deps)
  - `batch.py`   golden-corpus runner (1 sim session per disk batch —
                 cpmsim cannot see host-side disk image changes while running)
  - `disks/`     generated drive images (gitignored)
- `golden/`    — captured compilations (transcripts, .PRN, .REL)
- `probes/`    — black-box micro-test programs + their results
- `spec/`      — claims ledger + derived notes; the project's memory
- `grammar/`   — hand-built grammar of the accepted subset
- `ocaml/`     — (later) the reimplementation, dune project

## Oracle quickstart

    cd oracle && python3 batch.py DEMO --switches '$L$D'
    # manual session:
    python3 run.py --disks disks /tmp/script.txt
    # script lines: plain CP/M commands; ##WAIT <regex>; ##SEND <txt>; ##HALT

Prior related research (kept deliberately separate — see spec/CLAIMS.md

traces). This project is a pragmatic restart: small experiments, bounded

## Current status

The compiler is a live end-to-end pipeline (lexer → parser → binder → IR → codegen → `.REL`)
reproducing DR PL/I-80 v1.4 byte-for-byte, developed in operator-authorized numbered rounds
through **E2E-49/P4** (closed 2026-11-01).  The authoritative status lives in three places, not
here:

* [`spec/CLAIMS.md`](spec/CLAIMS.md) — the scientific ledger: every accepted law about DR's
  behaviour, with its specimen and golden evidence (ends at **C351**).
* [`PROGRESS.md`](PROGRESS.md) + [`HANDOFF.md`](HANDOFF.md) — working state and the one active
  action (rounds E2E-48/49 closed the FIXED/TEST string-compare family; E2E-50/P1 delivered the
  functional dashboard and is closed; E2E-50/P2 — active — built the functional-testing
  foundation: emulator audit, spec format, TABLE corpus, harness, first executed verdicts).
* [`docs/functional-status.md`](docs/functional-status.md) — the programmer-facing dashboard
  (generated by `tools/functional_dashboard.py --write`; never hand-edited): capability verdicts,
  stage ladders and representative programs derived from the committed evidence.
* [`docs/functional-results.md`](docs/functional-results.md) — the executed FUNCTIONAL verdicts
  (lane-labelled, typed), a rendering of `spec/lab-evidence/e2e50-p2/step{6,7}/RESULTS.md`; not a
  ledger and not a DR claim. Law: `spec/functional/tests/README.md`; tool: `tools/functional_runner.py`.
* [`docs/emulator-audit.md`](docs/emulator-audit.md) + [`docs/functional-testing.md`](docs/functional-testing.md)
  — the substrate capability matrix and redistribution audit, and the prose statement of the
  functional-testing law.
